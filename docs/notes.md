# 智能天气时钟（STM32F103 + ST7735 + ESP-01S）

一块 1.8 寸小屏上的桌面天气时钟：显示时间、当日天气、室内温湿度，最后一行轮播 6 页生活指数，右下角养了一只桌宠。

---

## 一、硬件

| 部件 | 型号 / 参数 | 接口 |
|---|---|---|
| MCU | STM32F103C8T6，72MHz，flash 128KB / SRAM 20KB | —— |
| 屏 | ST7735，128×160，RGB565，**只能写不能读** | SPI |
| WiFi | ESP-01S（AT 固件） | USART2，PA2/PA3，115200 |
| 温湿度 | DHT11（单总线，1 秒一次，走两段式采样） | GPIO |
| 时钟源 | 外部 LSE 32.768kHz，RTC 计数器当 Unix 秒 | —— |
| 调试口 | 串口打印（默认关闭） | USART1，PA9/PA10，9600 |

> VBAT 无电池，所以**开机必须联网校时**；只按复位键时 RTC 会保留上次时间（LSE 一直在走）。

**当前占用**：Code 28622 + RO 33486 ≈ 60.9KB / 128KB（48%）；RW 272 + ZI ≈ 7.4KB / 20KB（37%）。

| 区域 | 内容 |
|---|---|
| 开机画面 | 9 步进度条：系统 → 串口 → 屏 → ESP → WiFi → 校时 → 天气 → DHT11 → UI |
| 时间行 | `时:分:秒`（24×24 数字）。**RTC 未校时显示 `--:--:--`**，不显示 1970 |
| 日期行 | `11月2日` + `星期一` |
| 天气行 | 32×32 图标 + 当前温度 + ℃ + 最高/最低温，**负温用 3px 小负号**，右对齐 |

## 四、架构上的三个关键决定

### 1. 全工程只有一套取数流程

`Hardware/esp8266.c` 里是一个 **10 步状态机**（加上 `IDLE` 共 11 个状态）：

```
IDLE → CONN → MODE → PROMPT → WAIT → CLOSE → QUIET1 → QUIET2 → ESC → CIPCLOSE → END
```

- `ESP8266_ReqStart(kind, body, cap)` 发起后立刻返回；
- `ESP8266_Poll()` 每调一次**只推进一步**，返回 `0` 空闲 / `1` 在跑 / `2` 刚完成；
- `ESP8266_Result()` / `Kind()` / `Cost()` 取结果。

两个入口共用它：

| 入口 | 驱动方式 |
|---|---|
| 开机 `Net_Init` | 四个 `Get_xxx` 薄封装：`ReqStart` + `while (Poll() == 1) {}`，死等得起 |
| 主循环 `SD_NetRefresh` | 每 12ms 推进一步，不阻塞 |

**`ESP_POLL_GAP = 10`（毫秒）是这个模块的关键参数，绝对不要调小。** 原因见第六节。

### 2. 上屏数据全部经过 `screen_data.c`

屏幕不自己拼字符串、不自己格式化。`SD_FormatTemp / Time / Date / Week` 负责格式化，`SD_UpdateWeather`（比四个值）、`SD_UpdateRow`（比九个量）**都是“变了才画”**，一次网络失败不会清掉屏上已有的值。

### 3. 所有动画都是状态机

轮播、桌宠、DHT11 采样，全是“每圈推进一步”，主循环里**没有任何一处 `delay` 阻塞**。

## 五、关键参数（改行为先看这里）

### 刷新周期（`App/screen_data.c`）

| 宏 | 值 | 含义 |
|---|---|---|
| `SD_NOW_SEC` | 600 | 实况 10 分钟 |
| `SD_DAILY_SEC` | 21600 | 逐日 6 小时 |
| `SD_LIFE_SEC` | 86400 | 生活指数 24 小时 |
| `SD_TIME_SEC` | 86400 | 网络校时 24 小时 |
| `SD_TIME_RETRY` | 600 | 校时失败退避 10 分钟（否则一次失败要等一天） |
| `SD_RETRY_SEC` | 60 | 实况 / 逐日 / 生活指数取数失败后 60 秒重试 |

四个通道用 `if / else if` 串联，一圈最多发一个请求；时刻先写再请求。数据通道失败不傻等下一周期（实况一等就是 10 分钟），把下次时刻拉回 60 秒后重试；校时单独走 10 分钟退避，都不做重试风暴。

### 桌宠（`App/QDTFT.c`）

| 宏 | 值 | 含义 |
|---|---|---|
| `PET_BREATH_MS` | 900 | 呼吸相位间隔（下沉 / 上浮各 900ms） |
| `PET_BLINK_LO / HI` | 2500 / 6000 | 随机眨眼间隔，约 14 次/分钟 |
| `PET_LIFT_LO / HI` | 60000 / 180000 | 随机举爱心间隔 1~3 分钟 |
| `PET_SLEEP_ON / OFF` | 22 / 8 | 22:00 入睡，08:00 起床 |
| `pet_seq_lift[]` | 13 帧 | 连续举三下，共 2.9 秒 |

### 延时与时基（`System/delay.c`）

| 函数 | 特性 |
|---|---|
| `delay_us / delay_ms` | 忙等，别在长任务里用 |
| `delay_millis()` | **每 59652ms 回绕一次**，只能算“两次采样之间隔了多久”，**不能存未来时刻** |
| `delay_uptime()` | 按周期计数累加，49.7 天才回绕，**要存未来时刻就用它** |

## 六、踩过的坑（排查时先看这里）

| 现象 | 根因 | 解法 |
|---|---|---|
| 秒位一次跳好几秒、轮播停顿 | 四个 `Get_xxx` 同步阻塞，一圈卡 0.6~1.2 秒 | 改成 11 站点状态机，`Poll` 每圈一步 |
| 状态机化后**全部请求失败**，开机卡 40 秒 | 阻塞版 `WaitResult` 每 10ms 扫一次缓冲，天然有 0~10ms 盲区；状态机紧循环把盲区压到 0.1ms，模块还没收尾就被塞下一条命令，回 `busy p...` 或直接吞掉 | **`ESP_POLL_GAP = 10`**，把这段盲区显式写出来 |
| 桌宠眨十几次就永久停、爱心一次不出 | `delay_millis()` 每 59.6 秒回绕，代码却拿它存 `now + 间隔`，回绕后变成永远到不了的数 | 改用 `delay_uptime()` |
| 随机区间反了（只报 4 个 `#69-D` 警告） | `Pet_Rand(u16, u16)` 装 `180000` 被截断成 4864 | 参数改 `u32`，随机源取 24 位 |
| 舒适度一天算 720 万次 | `SD_UpdateRow` 每 12ms 无条件调 `SD_CalcComfort()` | 删掉，改到逐日数据**解析成功后**算一次（一天 4 次） |
| 每秒卡一下 | DHT11 `delay_ms(20)` 硬等 | 两段式 `DHT11_Start/Poll`；顺手修了“抬线后应立刻切输入”（原来推挽输出顶着高电平，等于和传感器抢线） |
| 未校时显示 1970 | 没判断 RTC 有效性 | `RTC_IsValid()`，画 `--:--:--`，用 `s_time_str[i]='-'` 当“该位已画”标记 |
| 霾天没有对应图标 | 天气码 31 被归并成“雾” | 自造 16×16 横线符号塞进 `hz16`（数组里写作 `"霾",`，GBK 字节 F6 B2），当“霾”字用，绘制代码零改动 |
| 晴天是个实心黄圆 | 圆盘直径 27px 撑满 32×32，没地方画光芒 | 换成八芒太阳（圆盘 13px），只换 512 字节，调色板没动 |
| `Gui_DrawFont_Num24` 越界 | 判据写死 `num > 12` | 改成 `(u16)num >= (u16)(sizeof(number_24)/48)`，随数组走 |
| **退透传失败把天气请求全毁** | `+++` 退透传要求前后各静默 1 秒，原代码只等 20ms，模块没退出去；此时发 `AT+CIPSTART`，整串 AT 命令被原样灌进还开着的 TCP 连接，天气接口返回两页 400 错误页——单模块测试全过、一集成就炸 | 退出序列拆成 `QUIET1 → ESC → QUIET2` 三个状态，前后各真等 1 秒 |
| **桌宠动画差点挤爆 flash** | 补丁帧数据让固件逼近 64KB——C8T6 实际多为 128KB，但官方只保证 64KB 稳定，不能赌 | 备选两案：外扩 W25Q64 存图库 / 脏矩阵刷新。选后者：每帧只描述变化的矩形，收尾一帧只重画约 114 像素，flash 压回 64KB 以内，还省一颗芯片 |
| **舒适度判定不可信** | 心知生活指数的舒适度，英文版与中文版档位对应错位（`Relatively comfortable` 等 6 档文档与实返回对不上），多日多次抓取比对后确认靠它判定效果不佳 | 弃用 API 的 comfort，改自算国标公式 `I = (1.8T+32) − 0.55(1−RH/100)(1.8T−26) − 3.2√V`，定点 ×100 |
| **校时总是慢 2~3 秒** | 时间戳从请求发出到拿到响应有传输耗时，外加服务器返回本身有延迟 | 校时计算时补偿：`ts += (请求耗时 + 固定偏移 + 500ms) / 1000` |

### 三个纯工程坑（不是代码逻辑，但都耽误过时间）

1. **源码必须 GBK + CRLF**。用 UTF-8 写 `.c/.h`，ARMCC 按 GBK 读会报 `#870-D` 加一堆中文乱码；`↔` 之类非 GBK 字符会截断成 0 字节。
2. **`.uvprojx` 不能有 BOM**，有就打不开（UV4 退出码 15）。
3. **Keil 关窗会把内存里的旧项目树写回 `.uvprojx`**，新加文件的登记会丢（`debug.c` 被抹过一次）。加文件之前先关 Keil。

## 八、已知取舍（不是 bug，是有意为之）

1. **开屏联网最长 85 秒无提示** —— 接受，不改。
2. **冒号不闪** —— 目前常亮。
3. **生活指数返回 23 项只用 4 项**（感冒 / 紫外线 / 空气 / 舒适度），其余未展示。
4. **未引用函数占用约 330 字节 flash** —— 工程未开 “One ELF Section per Function”，`Pet_Blink/Bob/Lift/Sleep`、`Lcd_ReadPoint`、`ESP8266_Close` 都在映像里；接受。
5. **风系（32~36）、大雨系（15~18）各共用一个图标桶**，不细拆；未知码的兜底桶沿用占位图，未换官方 99 号图。
6. 桌宠的四个阻塞版函数（`Pet_Blink/Bob/Lift/Sleep`）保留未删。

## 九、数据来源

- 天气：心知天气 API（`api.seniverse.com`），语言 `en` + 本地查表，城市用 ID（如：徐州 `WW56FQXV5ZHB`）
- 天气预报码表：<https://docs.seniverse.com/api/start/code.html>
- 时间：拼多多时间接口（无 Content-Length，必须等 `CLOSED`）
- 舒适度：国标 `I = (1.8T + 32) − 0.55(1 − RH/100)(1.8T − 26) − 3.2√V`，定点 ×100 计算，切点 4180 / 3140 / 990
